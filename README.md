# MAIS & OBAIDA — دعوة زفاف تفاعلية

React + Vite، واجهة عربية RTL، Netlify Functions، Postgres للإنتاج وNetlify Blobs للموسيقى. تشغيل محلي كامل بقاعدة SQLite فعلية (لا LocalStorage).

## التشغيل المحلي

يتطلب Node.js 22.13+ (يفضل أحدث Node 22 LTS).

```bash
npm install
npm run admin:create
npm run dev
```

- الدعوة: http://localhost:5173
- الإدارة: http://localhost:5173/admin/login
- `admin:create` يسأل عن اسم المستخدم ويُنشئ كلمة مرور عشوائية قوية، يعرضها مرة واحدة ويحفظ **الهاش فقط** وSESSION_SECRET في `.env`. احتفظ بكلمة المرور في مكان آمن.
- لا تُرفع `.env` أو `.data` إلى Git. إعادة إنشاء بيانات المدير تستلزم إعادة تشغيل السيرفر. لحذف الجلسات القديمة عند تغيير بيانات المدير نفّذ `DELETE FROM sessions;` على قاعدة البيانات.
- البيانات المحلية تحفظ داخل `.data/wedding.sqlite` والملفات داخل `.data/music`. لا توجد أسماء أو ردود وهمية.
- يعمل العرض بالإعدادات الافتراضية دون قاعدة Postgres. إرسال النماذج محليًا يتطلب توليد `.env` بالأمر أعلاه.

## متغيرات الإنتاج

| المتغير | القيمة |
|---|---|
| DATABASE_URL | رابط Postgres من Netlify Database أو مزود Postgres مع SSL وفق إعداد المزود |
| ADMIN_USERNAME | اسم مستخدم المدير |
| ADMIN_PASSWORD_HASH | قيمة scrypt التي ينشئها `npm run admin:create` |
| SESSION_SECRET | سر عشوائي طويل ينشئه الأمر نفسه، 32 حرفًا على الأقل |
| SITE_URL | اختياري: الرابط النهائي للموقع لصورة المشاركة؛ يُستخدم URL الخاص بـ Netlify تلقائيًا إن توفر |

`NETLIFY_DATABASE_URL` مدعوم بديلًا لـ `DATABASE_URL`. لا يوجد أي سر داخل كود الواجهة.

## النشر على Netlify

1. ارفع المشروع إلى مستودع Git خاص، واربطه بموقع Netlify جديد.
2. جهّز قاعدة Netlify Database / Postgres وأضف المتغيرات أعلاه إلى Netlify (Functions، وSITE_URL إلى Build).
3. ضع رابط Postgres في `.env` محليًا ثم شغّل `npm run db:migrate` مرة واحدة. ترحيل SQL قابل للتكرار دون حذف البيانات. يمكن تطبيق الملف بأداة SQL لدى مزود القاعدة.
4. Netlify يقرأ `netlify.toml`: البناء `npm run build`، النشر `dist`، الوظائف `netlify/functions`.
5. انشر واختبر الدخول وإرسال رد ورفع أغنية على رابط الإنتاج. Netlify Blobs يُربط تلقائيًا داخل Functions. لا تعتمد على رفع مجلد `dist` وحده بالسحب والإفلات، فهو لا ينشر الوظائف.

لا يستخدم الإنتاج SQLite ولا يحوّل فشل Postgres إلى تخزين مؤقت. لم تُنشأ خدمة Netlify أو قاعدة خارجية من بيئة التسليم؛ يلزم ربط حسابك والمتغيرات ثم النشر.

للتجربة عبر Netlify CLI عند توفره: `netlify dev`؛ أما `npm run dev` فيشغّل API محليًا بالفعل دون الحاجة إلى CLI. `npm run preview` يعرض ملفات الواجهة المبنية فقط وليس API؛ استخدم dev لاختبار النماذج.

## الموسيقى

ملف افتراضي أصلي قصير وهادئ مرفق في `public/music/wedding.mp3`، ويمكن استبداله مباشرة أو رفع أغنية من تبويب «الموسيقى» في الإدارة. الصيغ MP3/M4A/WAV، حد 4 MiB ليتناسب مع حمولة Netlify Functions. استخدم ملفًا مسموحًا لك بمشاركته؛ يمكن ضغط الأغاني الطويلة بصيغة MP3.

الرفع يفحص الامتداد وتوقيع الملف، يخزّن البايتات في Netlify Blobs بالإنتاج والرابط فقط في الإعدادات. يدعم HTTP Range للتقديم داخل الأغنية على iPhone. يبدأ الصوت بعد ضغط فتح الدعوة، ولا يؤثر فشله على الدعوة. زر الاستعادة يعيد اللحن الافتراضي.

## الإدارة والخصوصية

- إحصائيات الردود والضيوف، بحث بالاسم/الهاتف، فلاتر الحضور، صفحات للنتائج.
- الموافقة على الرسائل أو إخفاؤها أو حذفها بعد تأكيد. اختيار ظهور الرسائل مباشرة أو انتظار الموافقة.
- تعديل الأسماء والتاريخ والوقت وIANA timezone والمكان ورابط الخرائط والنصوص.
- الإعدادات الجديدة تظهر عند إعادة فتح/تحديث الدعوة أو العودة لتبويبها، ويُعاد جلبها كل دقيقة في التبويب المفتوح.
- رابط القاعة الافتراضي **بحث Google Maps** وليس إحداثيات قاعة موثّقة؛ استبدله بالرابط الدقيق من الإعدادات.
- ملفات ICS وروابط Google Calendar تستخدم المنطقة الزمنية المحددة. نهاية الحدث افتراضيًا بعد 4 ساعات.
- أرقام الهاتف ورسائل RSVP خاصة. رسائل Guestbook وحدها عامة بحسب الموافقة.
- جلسات عشوائية لمدة 12 ساعة، محفوظة كهاش في القاعدة، HttpOnly / SameSite=Strict / Secure بالإنتاج، وإبطال فعلي عند الخروج.
- حماية Origin ضد CSRF، تحقق خادمي Zod، منع HTML، SQL بمعاملات، rate limit محفوظ في قاعدة البيانات، وحقل honeypot.
- لا تسجّل الأسرار ولا تخزن ملفات الصوت داخل قاعدة البيانات. خطّط لنسخ Postgres احتياطيًا عبر مزودك قبل دعوة ضيوف حقيقيين.

## الصور والخطوط والمشاركة

خلفية أصلية مولّدة للمشروع في `public/images/lake.webp`، نسخة عريضة وصورة مشاركة `cover.jpg`. خطوط Google Fonts مستضافة داخل المشروع مع تراخيص OFL، بدون اتصال خارجي لتحميل الخطوط. الخلفية مضغوطة WebP.

Open Graph والعنوان الافتراضيان ضمن `index.html`، ويتم تحويل رابط صورة المشاركة إلى عنوان كامل أثناء build. عند تغيير أسماء الحدث بعد النشر، عنوان الصفحة داخل المتصفح يتحدّث تلقائيًا؛ حدّث وسوم المشاركة في `index.html` وأعد النشر لتحديث المعاينة على تطبيقات التواصل (وقد تحتفظ تلك التطبيقات بكاش).

## الملفات الرئيسية

- `src/components/Invitation.jsx`: الافتتاحية والموسيقى والدعوة والنماذج والعد التنازلي.
- `src/components/Admin.jsx`: لوحة الإدارة.
- `src/style.css`: تصميم الموبايل والكمبيوتر، حالات التركيز وتقليل الحركة.
- `server/api.mjs`: API + حماية المسارات + رفع الموسيقى.
- `server/db.mjs`: محول Postgres / SQLite المحلي.
- `server/security.mjs`, `server/validation.mjs`: الأمن والتحقق.
- `netlify/database/migrations/001_wedding.sql`: الجداول والفهارس.
- `netlify/functions/api.mjs`, `netlify.toml`: نشر Netlify.
